### Day 2
* **Planned:** Build the custom Gym Environment (`ransac_env.py`). Implement `reset()` and basic `step()` function bridging to Cython.
* **Done:** Created `ransac_env.py` to wrap the Schnabel Cython module for RL.
* **What Went Wrong:** The initial implementation was built as a "1-shot" continuous environment (ending after 1 step), which failed to support the Phase 1 requirement of a 5-step sequential decision process.
* **Fixed:** Refactored the environment heavily. Converted the action space to `MultiDiscrete([8, 6, 2])` (epsilon, min_support, stop/continue) and implemented logic to allow up to 5 steps per episode.
* **Result:** The environment correctly holds state across steps and properly delays episode termination.

### Day 3
* **Planned:** Implement the 28-dim State Builder (Scene & Feedback features).
* **Done:** Implemented `scene_features.py` which calculates geometric properties of the point cloud.
* **What Went Wrong:** 
  1. The dataset `.ply` files lacked an intensity/reflectivity channel, meaning the planned 18 scene features could not be used verbatim. 
  2. The initial prototype completely missed the critical 10 "feedback features" (e.g., previous actions, inlier ratio history).
* **Fixed:** 
  1. Replaced the missing intensity features with 21 robust geometric features (using Open3D for normal variance and PCA) to compensate for the lost data. 
  2. Injected the 10 feedback features directly into `ransac_env.py`'s observation array.
* **Result:** We now have an even richer **31-dimensional state space** that correctly tracks the agent's historical context.

### Day 4
* **Planned:** Implement the Self-Supervised Reward Function.
* **Done:** Added reward calculation logic to `step()` in the Gym environment.
* **What Went Wrong:** The original prototype used a very basic heuristic `(ground_pct * 10.0) + (z_align * 2.0)` applied at every single step, which would have broken sequential learning.
* **Fixed:** Overwrote the logic to strictly follow the Phase 1 formula: `(1.0 * inlier_ratio) - (0.1 * runtime) - (0.5 * mean_residual) + (0.3 * normal_consistency) - (0.05 * step_count)`. Forced the reward to only be calculated on terminal states (`stop` action or max steps reached).
* **Result:** The environment properly penalizes the agent for running too slowly or using too many steps, and rewards tight, accurate ground fits.

### Day 5
* **Planned:** Set up the PPO Agent architecture (`train_rl.py`) for the 3-action space.
* **Done:** Developed `train_rl.py` using Stable Baselines3's `PPO` and `MlpPolicy`.
* **What Went Wrong:** There was a concern that SB3 wouldn't handle the new `MultiDiscrete` action space we introduced on Day 2.
* **Fixed:** Verified that Stable Baselines3 inherently supports `MultiDiscrete` spaces natively without any custom architecture changes.
* **Result:** Wrote a test script (`test_step.py`) verifying that the environment processes actions flawlessly. `train_rl.py` is verified and ready for the first major training session.

## Week 2

### Day 6
* **Planned:** Enhance the environment sampling logic to support multi-folder training and adaptive difficulty (Hard-Negative Mining).
* **Done:** Updated `ransac_env.py` to recursively discover `.ply` files across all dataset folders and implemented an Exponential Moving Average (EMA) to track the agent's performance on each terrain.
* **What Went Wrong:** A uniform random sampling strategy across all files would cause massive datasets to overshadow small ones, preventing the agent from learning diverse terrains. Additionally, temporary `cache` folders from dataset downloads risked breaking the script.
* **Fixed:** 
  1. Filtered out any paths containing `"cache"`.
  2. Implemented an Adaptive Softmax Sampling mechanism in `reset()`. The environment now explicitly groups files by their parent folder, checks their average reward, and heavily biases the next random selection toward the folders with the worst scores.
  3. Added the fixed `0.05m` Voxel Downsampling step using `Open3D` to the `.ply` loader as dictated by the Phase 1 architectural diagram.
* **Result:** The agent now actively hunts down its weaknesses. If it struggles on "Sewerage", it will force itself to practice on "Sewerage" until it masters it. Downsampling has also drastically sped up RANSAC execution time.

### Day 8

  2. Separately found `baseline_evaluator.py` is currently broken — it calls `env._unnormalize_action()`, a method that no longer exists after the Day 2 `MultiDiscrete` action-space refactor. Baselines cannot currently be regenerated or extended to new datasets without fixing this script first.
* **Fixed:**
  1. Patched `find_ground_plane()`'s two early returns to consistently return 4 values (`None, None, None, None`).

Added `ent_coef=0.01` and wrapped the training env in `VecNormalize(norm_obs=True, norm_reward=True, clip_obs=10.0)` in `train_rl.py`, plus a `--vecnormalize` resume flag and matching stat-saving on both the normal-completion and `KeyboardInterrupt` exit paths (needed so eval scripts can later load the same normalization stats the model was trained with).
  4. `baseline_evaluator.py`'s `_unnormalize_action` bug is identified but **not yet fixed**.
* **Result:** `train_rl.py` is ready for a retrain with the entropy/normalization fix, but retraining has **not** been run yet. ### Day 10
* **Planned:** Redesign the reward function to finally address the one open item Day 8/9 didn't touch — `mean_steps` pinned at 1.0 across every dataset, meaning the agent never uses the 5-step sequential refinement the whole architecture was built around. Then retrain and compare against the Day 9 model as a new, non-destructive version.
* **Done:**
  1. **Diagnosed why steps never got used:** under the old formula, reward was `0.0` for every non-terminal step — the agent had zero signal about whether an intermediate refinement step actually helped, only a single lump-sum reward at the very end. The only thing steering the "continue or stop" decision was a flat `-0.05 * step_count` penalty, which apparently dominated the small, uncertain potential gains from refining (inlier ratios here are typically only 0.03-0.3).
  2. **Redesigned the reward as potential-based shaping** in `ransac_env.py`'s `step()`: defined `Φ(state) = 1.0*inlier_ratio - 0.5*mean_residual` (the parts that actually change per step), and every step now gets `reward = [Φ(new) - Φ(prev)] - 0.1*runtime - 0.01`, with `normal_consistency` (a static per-frame scene feature, can't respond to actions) added once as a `+0.3` bonus only at the terminal step rather than folded into the per-step potential (folding it in would make it cancel out of every delta, silently erasing it from the training signal — worked this out by hand-tracing the telescoping sum before implementing). Step penalty reduced from `0.05` to `0.01` since it's now a tie-breaker on top of real signal, not the only signal. Total episode return still recovers the exact same terms as the original formula (same shape, just paid out incrementally) — this is a reward-shaping change, not a new objective.
  3. Smoke-tested manually (5 forced steps, same action repeated): step 1 got a real `+0.097` (genuine improvement from the zero baseline), steps 2-4 (no further improvement, same action/result) got a small `~-0.025` each as intended, step 5 (terminal) included the `+0.3*normal_consistency` bonus. Confirms the shaping behaves exactly as designed before spending any training compute on it.
  4. **Added a `--tag` argument to `train_rl.py`** (checkpoints/final model/vecnormalize/training-log filenames all get the tag baked in, e.g. `ppo_ransac_v2_reward_final.zip`, `evaluation_metrics_v2_reward.csv`) so this run doesn't touch any of the Day 9 model's files. `rl_evaluator.py` already had matching `--tag` support (writes `<env>_rl_<tag>.csv`) and `per_frame_comparison.py` already auto-discovers every `<env>_rl*.csv` present — both apparently prepped for this ahead of time.
  5. Plan going forward: pilot ~10,000 steps first (tag `v2_reward`) and check whether `mean_steps` actually moves off 1.0 before committing to the full 50,000-step run, training from scratch rather than resuming from the Day 9 model (the reward's meaning changed enough that continuing from a policy trained under the old incentive structure risks carrying over the "always stop at step 1" bias rather than cleanly learning the new one).
* **Result:** Reward redesign implemented and verified in isolation; training not yet run. Day 9's model/data (`ppo_ransac_final.zip`, `<env>_rl.csv`) remain fully intact and untouched throughout.

### Day 12
* **Planned:** Investigate a suspected reward-shaping bug flagged while reviewing the reward formula against the live `v3_normthresh_heldout` run: a large positive reward logged at a step where plane quality had clearly gotten worse, not better.
* **Done:**
  1. Confirmed the bug analytically against a concrete logged example: `Φ = inlier_ratio - 0.5*mean_residual` dropped from `0.0897` (step 3: inlier_ratio 0.1416, residual 0.1038) to `0.00975` (step 4: inlier_ratio 0.0139, residual 0.0083) -- a genuine ~`-0.09` shaping penalty -- but the terminal-only `+0.3 * normal_consistency` bonus (`normal_consistency` sits at ~0.99 for nearly every frame) overwhelmed it, flipping the sign to the logged `+0.197`.
  2. Root-caused why: `normal_consistency` (`current_features[17]`) is computed once per episode in `reset()`, before any RANSAC call -- a static per-frame descriptor, completely independent of `eps`/`min_support`/`norm_th` or which plane actually got detected that step. Adding it as a flat bonus only at the terminal transition breaks potential-based shaping's telescoping-sum property (a term that doesn't cancel across the episode isn't policy-invariant), and since this one barely varies at all, it functioned as a near-constant reward for terminating, regardless of final detection quality.
  3. Found live evidence this was actively happening, not theoretical: pulled the tail of `logs/evaluation_metrics_v3_normthresh_heldout.csv` from the currently-running training process (~17,240/40,000 steps into a resumed run) -- the overwhelming majority of recent episodes showed `steps_used=1`. Same `mean_steps`-collapse symptom already fought once in Day 10/11, resurfacing under the Day 11 4-action (`normal_thresh`-inclusive) expansion.
  4. Computed real distributions across all 141,435 logged steps in `logs/evaluation_metrics*.csv` to ground the fix: `inlier_ratio` p90=0.234, max=0.447 (never gets very large in this data); the candidate replacement signal `z_align` (`find_ground_plane`'s per-step, actually-detected-plane `|normal_z|`, already computed every step but discarded) is close to bimodal (p25=0.03, median=0.95), a direct consequence of `find_ground_plane`'s `horizontal_thresh=0.80` gate.
* **What Went Wrong:** The terminal bonus was doubly broken -- structurally invalid as reward shaping (doesn't telescope, so it isn't policy-invariant) and computed from a feature that literally cannot respond to the agent's actions within an episode, making it worse than "usually close to 1": it never varies at all across a given frame's steps, so it carried zero credit-assignment information about whether stopping there was actually a good decision.
* **Fixed:**
  1. Removed the standalone `+ 0.3 * normal_consistency` terminal bonus from both the terminal path and the `too_few_points` path in `ransac_env.py::step()`.
  2. Added persistent `self.z_align` tracking (mirroring `self.inlier_ratio`/`self.mean_residual`) and folded it directly into `_potential()`: `Φ = inlier_ratio - 0.5*mean_residual + w*z_align`, so it telescopes across the episode like the other two terms instead of being bolted onto one transition.
  3. Weighted at `w=0.3` initially (matching the old bonus's magnitude), then reduced to `w=0.15` after the distribution analysis showed `0.3` would let a single `horizontal_thresh` gate-crossing (up to `+0.3`) dominate over the *entire* observed range of `inlier_ratio` improvements (max `0.447`) -- i.e. over the primary objective itself.
  4. **Not applied retroactively** to the live `v3_normthresh_heldout` run -- deliberately left it training under the old reward rather than interrupting in-progress compute; the fix takes effect on the next fresh `train_rl.py` invocation.
  5. Updated `ADAPTIVE_RL_PLAN.md` and `RL_PIPELINE_OVERVIEW.md`'s reward-function sections and Known Issues to reflect the change, matching the Day 10 documentation pattern.
* **Result:** Reward-shaping fix implemented and verified in isolation (`python -m py_compile ransac_env.py` clean). Next training run should start from a clean/earlier checkpoint rather than resuming from the `v3_normthresh_heldout` lineage's `_final.zip`, since that model's weights were shaped under the old (now-confirmed-biased) terminal bonus across v1/v2/v3 and likely already carry the "stop immediately" bias this fix targets. Plan going forward: let the in-progress `v3_normthresh_heldout` run finish as a documented "before" data point, then train a new, separately-tagged run (from scratch) under the corrected reward for a clean before/after comparison.
